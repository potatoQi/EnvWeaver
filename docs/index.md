# 项目简介

EnvWeaver 是一个 Python 包，为 Data Pipeline、评测和训练提供统一的沙箱操作、验证接口和任务格式。不同 Pipeline 生成的任务可以保存为同一种 Task，供下游读取和使用。

Runtime 负责启动、操作和保存沙箱；Verifier 负责运行验证程序并返回得分；Task 将任务要求、环境引用、输入材料和验证程序保存为任务包。

## Data Pipeline：保留各自的流程，统一保存的任务格式

Coding、终端操作、桌面操作等领域有各自的 Data Pipeline。把它们重写成一个通用 Pipeline，成本高，已有代码也需要重新适配。强行统一生产步骤，还可能删掉某些任务特有的构造和检查方法，而这些方法往往决定了任务的难度和价值。

使用 EnvWeaver 时，已有 Pipeline 可以保留自己的处理步骤，将结果按 Task 格式保存。新 Pipeline 可以由 Agent 或开发者编写，使用 Runtime 准备沙箱、使用 Verifier 检查任务。Pipeline 自己决定怎么生成任务，最后按 Task 格式保存即可。

## Evaluation：不同验证方法，使用同一个调用接口

有的任务用规则和测试判分，有的让 Agent 判分，有的结合规则与 VLM。有的验证程序只检查提交的文件，有的需要进入任务沙箱，截图、读取文件或运行测试。如果每种方法都有不同的调用方式和结果格式，评测程序就要分别编写适配代码。

Verifier 规定如何传入任务沙箱、文件和环境变量，以及验证程序如何返回得分。验证程序在验证沙箱中运行，可以直接检查提交的文件，也可以通过 Runtime 操作任务沙箱。具体检查什么、怎样评分，由验证程序决定。

评测程序读取 Task、准备环境、让 Agent 完成任务，然后通过同一个 Verifier 接口运行任务附带的验证程序、读取得分。制作任务时，Pipeline 也可以使用这个验证程序，检查正确答案是否得分、错误答案是否被识别。

## Training：不同来源的任务，使用同一套读取和执行流程

任务格式不一致时，训练程序需要针对每种数据分别处理任务说明、准备环境、放入材料和调用验证程序。每增加一种任务，都可能要再写一套处理代码。

Task 用相同的字段记录这些信息。训练程序按这些字段读取任务要求、启动环境、复制材料并执行准备操作，再让模型完成任务，最后调用验证程序取得得分。每道题需要执行的准备操作和评分方法由 Task 提供，训练程序可以复用这套流程。
