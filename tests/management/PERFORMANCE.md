# 管理界面性能检查

本次在当前服务器上对比优化前后耗时；浏览器连接本机 8788 端口。下表是单次对照值，不是延迟保证；磁盘缓存、任务文件数量和网络都会影响结果。

## 实测

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 已选择的真实 Pool（89 题），浏览器首次显示列表 | 0.87 s | 0.12 s |
| 同一页面按名称搜索，含 250 ms 输入防抖 | 0.86 s | 0.36 s |
| 首屏列表响应正文，不含静态资源 | 271 KB | 9 KB |
| 临时 Pool（500 题），首次打开并建索引 | 3.48 s | 0.34 s |
| 500 题 Pool，获取一页列表和全部筛选选项 | 1.06 s，4 次请求 | 0.096 s，1 次请求 |
| 500 题 Pool，批量增加标签 | 1.11 s | 0.92 s |

临时任务每条有约 9.5 KB 的文字、图片、context 文件和验证程序，分页大小为 30。通过 FastAPI TestClient 统计请求耗时和 PoolFiles 调用次数；真实页面使用 Chromium Performance API 和界面可见时间计时。写操作仅在临时 Pool 执行。

首次建索引主要耗时来自重复扫描和逐条复制整份内存索引。刷新主要耗时来自四个请求各自扫描 Pool，以及列表返回完整 Task。批量写入原本逐条调用 PoolFiles，远端会逐条执行 SSH；现在每个 Pool 合并一次批量调用，但保留每个文件的独立冲突检查、原子替换和持久化写入，因此本地写入提速相对较小。

真实页面观察期未检测到超过 50 ms 的浏览器主线程任务。空闲七秒期间仅执行两轮索引/操作状态检查，没有再次拉取列表。

## 正确性验收

- 分页摘要只扫描一次；筛选选项覆盖整个当前 Pool，完整 JSON 不进入列表响应。
- 未变化的记录跳过 JSON 解析；嵌套文件变化、SDK 保存和符号链接仍被检测。
- 一批记录中有无效数据时，有效记录仍被索引；修复后可以重新发现。
- 批量写入第二条记录遇到外部修改时停止，保留外部内容；刷新显示已成功的部分，重试只写剩余修改。
- 延迟返回的旧搜索结果不能覆盖新结果。
- 外部新增任务自动显示；无变化时不重复加载列表。
- 页面隐藏时不发新轮询；模拟四秒慢响应后，下一次轮询仍等待上一次完成，不堆积请求。
- 真实 SSH 使用临时本机 sshd 验证任务/环境读取和修改，多个任务标签写入共用一次远端批量操作；服务在测试结束后关闭，测试文件仅写入临时目录。
- 实际检查 1440px 和 390px 页面，无页面级横向溢出；宽表格在自身区域滚动。

## 范围

仍需递归检查文件属性，以发现 SDK 和其他程序的修改；没有通过长期缓存跳过变更检测。未测数万条任务、海量材料文件或跨公网 SSH 的性能；本机 SSH 验证通信和批量处理正确性，不代表公网速度。真实 Pool 只读检查，批量修改使用临时数据。


## 详情访问优化

使用同一 89 题 Pool，Chromium 依次打开 Task、跳转共享验证环境、返回 Task。单次本机对照（含浏览器自动化点击开销）：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 打开 Task 详情至可见 | 157 ms | 62 ms |
| 跳转共享验证环境至可见 | 134 ms | 115 ms |
| 返回 Task 至可见 | 119 ms | 111 ms |
| Task 详情正文传输量 | 15.3 KB | 2.6 KB |
| 共享环境详情正文传输量 | 818.6 KB | 83.4 KB |

详情直接返回标签定义，省去一个串行请求；完整关联资产仍保留。JSON 响应压缩，原始下载文件不压缩。scandir 遍历减少文件属性查询和路径对象分配，保持原文件指纹及变更检测。折叠的 Task JSON 延迟高亮，文件列表和图片独立加载，图片并发上限为 4。

新增验证包括：新旧文件指纹一致、内容/权限/文件替换仍被识别；gzip 解码后 JSON 完全一致、二进制下载字节不变；跨 Pool 访问读取目标 Pool 的最新内容和标签；延迟三秒返回文件列表时图片先显示；详情切换/关闭后迟到的结果不覆盖界面；返回和页面刷新保留滚动位置及 JSON 展开状态。

以上延迟不代表跨公网或 SSH 的速度。返回操作的本机改善较小，主要传输收益来自大详情响应及减少网络往返。

## casia23 远程 Traj Pool

2026-10-30 在 casia35 读取 casia23 的真实 Pool，生产目录仅做读取。实验期间记录数变化（约 745～976 条），以下为单次观察值，不能视为稳定延迟保证。

- 原扫描本身在远端约 1.30 s，首次取回约 3.3 MB 索引响应耗时 48.14 s。原服务日志同时存在 SSH 握手超时与连接重置。
- SSH 连接复用与压缩后，单独索引读取曾达到 3.45 s；跨多轮测量仍出现数十秒等待。TCP 状态显示大量重传，应用优化无法消除链路丢包。
- 加入目录摘要比对和远端执行代码缓存后，同一进程连续三次真实刷新为 1.042、0.484、0.246 s；该轮首次连接并建索引仍需 35.156 s。数据首次传输和新连接仍受网络影响。

目录摘要比对仍扫描所有文件属性。未变化时省去全量指纹传输，变化时获取增量记录；不通过缓存有效期隐藏外部修改。文件列表和预览直接读取目标，不扫描全池；远程路径检查与字节读取在同一次调用完成。扫描不持有内存索引锁，应用前重新核对版本，并发编辑后重新扫描。

回归覆盖：外部文件新增、删除和内容修改；Pool 注释变化；嵌套文件和符号链接；扫描期间读取与编辑；原始二进制字节；SSH 批量写入、冲突及删除；执行代码缓存缺失、损坏、版本变化、不可写，以及操作错误不被重放。浏览器检查使用现有完整管理流程测试。

更新 8788 服务并恢复原有 Pool 选择后，Chromium 在真实远程 Pool（768 条记录）实测：切换 Traj Pool 4.918 s，展开分组 1.989 s，打开详情 1.964 s，轨迹与文件列表全部可见 2.995 s，无浏览器脚本错误。另一次列表切换为 0.239 s；网络波动仍明显。分组加载期间后台轮询不再发起刷新或取消展开请求；慢响应浏览器回归覆盖此情况。切换目录立即清空旧条目，返回同一目录仍正常重绘列表。
